## 2. What I built

**Feature:** the core UI (consent, index status, chat with citations,
citation viewer) plus making `api/routes/documents.py` real -- it was the
one remaining S1 fixture route and the citation viewer needs real data to
preview/open/reveal.

**Scope done:**

- **Folder consent screen** (`ui/src/pages/Consent.jsx`): existing
  add/revoke-folder UI kept, now also shows and toggles global indexing
  pause/resume (`POST /api/index/pause` / `/resume`, already real since
  S2/S3 -- this session only wired the UI to it).
- **Indexing status** (`ui/src/pages/IndexStatus.jsx`, new page + nav
  item): polls `GET /api/index/status` every 4s, shows state (idle /
  scanning / indexing / paused / error), folder counts, documents/chunks
  indexed, last run time, and a pause/resume control.
- **Chat interface** (`ui/src/pages/Chat.jsx`): unchanged request flow,
  now renders citation chips per assistant message (`label: filename
  p.N`, clickable) and an "unverified" badge when `grounded: false`,
  with the verification reason as a tooltip.
- **Citation viewer** (`ui/src/components/CitationViewer.jsx`, new,
  modal): fetches `GET /api/documents/{hash}/preview` for the clicked
  citation, shows the quote, path, page, and "also found at" duplicates,
  and has "Open original" / "Reveal in file manager" buttons wired to the
  (now real) open/reveal endpoints.
- **`api/routes/documents.py` made real**: `GET /{hash}` and `/preview`
  now query `documents` / `file_locations` / `chunks` / `facts` directly
  and 404 on an unindexed hash instead of always returning fixture data.
  `open`/`reveal` resolve the best known on-disk path and shell out to the
  platform's default opener (`open`/`xdg-open`/`explorer`), reporting
  `opened: false` with a message on any failure (missing file, headless
  box, no matching path) rather than raising.

**Not done / cut:**

- No streaming in chat (unchanged from S3 scope; still out of scope here).
- The indexing-status page polls rather than pushing (no websocket/SSE) --
  fine at 4s for a local single-user tool, flagged if S5+ wants push.
- `open`/`reveal` are best-effort and untested against a real desktop
  (this session's sandbox is headless); the failure path (`opened: false`
  + message) is exercised by the new test and by manual curl, but nobody
  has clicked the button on an actual Mac/Windows/Linux desktop yet.

## 5. Known issues

**Issue 1: open/reveal are unverified on a real desktop.** Blocks demo?
Possibly, if clicked live. Workaround: the citation viewer always shows
the path and quote even if open/reveal fails, so the demo can fall back to
"here's the path" narration. `_shell_open` in `documents.py` is a small,
isolated function if it needs platform-specific fixes.

**Issue 2: indexing status polling, not push.** Blocks demo? No. A 4s
poll is imperceptible for a local single-user demo. Flagged in case a
future session wants a live progress bar during a large re-index.

**Issue 3 (inherited from S3, still true): the 3B model can refuse
answerable questions, and cold-start can hit the chat timeout.** See
`docs/handovers/S3.md` sections "Known issues" 1 and 3 -- unchanged by
this session. The reliable demo phrasing is still *"When does my Dell
laptop warranty expire?"*, and the model should be warmed before a demo.
